# 雀记最终 UI 基准

> 唯一视觉基座：`麻将记分 App 设计系统与界面流程板.png`（最终高保真）。
> 后续产品讨论只允许调整业务结构与状态，不重新发明视觉语言。

## 1. Design Foundations

- App Background: `#F8F7F2`
- Card: `#FFFFFF`
- Accent: `#F3B43F`
- Accent Soft: `#FFF2D5`
- Success: `#2C8C63`
- Danger: `#D6504F`
- 主文字: `#1C1C1E`
- 页面采用暖白底、白色卡片、轻边界、克制圆角；避免明显阴影和大面积玻璃效果。
- 页面信息密度遵循 iPhone 原生应用：标题清晰、卡片紧凑、首屏尽量完整呈现关键操作。
- 一级页面标题与微信右上角系统胶囊处于同一视觉导航行，右侧主动留出系统胶囊安全区域，不从胶囊底部再开始页面内容。

## 2. 全局导航

底部仅保留 4 个一级 Tab：

1. 首页
2. 组局
3. 牌友
4. 我的

采用固定融入式 iOS Tab Bar，不做悬浮胶囊；选中态仅使用品牌黄色图标/文字强调。

## 3. 首页

视觉骨架沿用高保真“今天打几圈？”：

- 小品牌说明 + `今天打几圈？`
- 浅黄色“今日战绩”卡
- 当前进行中的牌局卡；无进行中牌局时显示“开始新牌局”
- 最近约 3 场牌局

产品修订：

- 首页不出现自摸、点炮、局内事件、录入牌谱等直接录分入口。
- 多个进行中牌局仅展示最近操作的一场。
- 牌局名称可选；永不展示“未命名牌局”。

## 4. 组局

内部固定 3 个状态：`正在组局 / 我的组局 / 群聊`。

- 页面主标题随当前内部 Tab 变化，避免重复的“组局 + 分区标题”。
- 组局卡保持高保真紧凑密度：时间、地点最强；标签次要；头像堆叠 + 人数；小型黄色主动作。
- `群聊` 是会话列表，再进入群聊详情。
- 未读从底部 `组局` → `群聊` → 会话逐级传递。
- 仅支持现有 text/system 消息，不展示虚假的图片入口。

产品修订：

- 组局阶段不出现东南西北。
- 邀请、分享、二维码都只代表“加入这桌/加入组局”，绝不绑定座位。
- 4 位成员确认后，才进入座位分配。

## 5. 开局准备桌与座位

### 准备桌

- 四个位置只是参与名额，不是座位。
- 登录用户不自动占位；可以手动选择自己。
- 空位支持：自己、已有牌友、微信邀请、二维码加入。

### 座位确认

- 四人到齐后进入座位确认。
- 此时才展示 `东·庄 / 南 / 西 / 北`。
- 房主明确分配四位玩家；加入顺序、邀请顺序、原视觉位置都不能自动决定座位。
- 东家自动成为初始庄家。
- 普通准备桌与组局开局共用同一个 Seat Assignment。

## 6. 进行中牌局

沿用高保真牌局概览语言，并叠加最终业务结构：

- 顶部紧凑返回 + 标题 + 当前风圈/局数。
- 四人一整块横向比分区，不做 2×2 独立牌友卡。
- 展示头像、昵称、东南西北、庄家、当前分数。
- 页面中部固定 2×2：`自摸 / 点炮 / 流局 / 局内事件`。
- 最近约 3 条记录；提供“全部记录”和“撤销上一条”。
- 无 `战况 / 记录` Segmented Control。
- `录入牌谱` 不作为独立主入口。

## 7. 录分 Modal

统一使用最终高保真的居中白色 Modal：

- 四位玩家位置固定。
- 选中态：黄色描边 + 浅黄底 + ✓。
- 分值区突出一个主数字，快捷分值为小按钮。
- `本次分数变化` 仅做预览。
- 最终唯一主动作：黄色 `确认保存`。

业务规则：

- 自摸：默认不选人；当前登录用户为胡牌者时才允许录入自己的牌谱。
- 点炮：必须先选点炮者，再选胡牌者；点炮者在胡牌者选择阶段保留位置但禁用。
- 一炮多响：每次新记录默认关闭；打开后可选 2–3 位胡牌者。
- 流局：预览庄家结果，按现有规则处理，不手动选庄。
- 局内事件：`明杠 / 暗杠 / 花杠 / 被跟圈 / 四风归一`，保持既有计分语义。
- 牌谱与记分在同一个 Modal 内切换，最终随记分一次提交。

## 8. 微信登录与资料完善

登录页沿用高保真：简单微信图形 + 单一黄色主按钮。

资料完善：

- 昵称必填。
- 性别必选。
- 头像可选。
- 未选择头像时，根据性别生成默认头像。
- 结构为：头像行 → 昵称 → 性别 → 默认头像预览 → 黄色完成按钮。

## 9. 牌友

牌友根页采用高保真列表，不做卡片墙：

- 大头像、昵称、关系摘要。
- 微信真人和手工牌友使用同一套视觉。
- 右侧展示“我与该牌友共同牌局中的关系净分”，并附共同将数。

牌友详情聚焦 `我 vs 他`：

- 共同将/局。
- 我胡牌 / 他胡牌。
- 我点炮给他 / 他点炮给我。
- 关系净分。
- 唯一一张共同牌局净分走势。
- 大胡记录作为次级信息。

身份绑定：

- 微信真人与当前用户拥有的手工牌友一对一私有绑定。
- 绑定只聚合查询口径，不改写旧牌局。
- 解绑后重新拆分。

## 10. 我的与战绩

`我的` 根页只保留：

- 个人资料。
- 我的牌风。
- 我的战绩入口。
- 设置入口。

根页不是统计仪表盘；牌风必须基于真实数据描述。

`我的战绩`：

- 日 / 月 / 年，默认月。
- 顶部仅四项：`胡牌率 / 自摸率 / 点炮率 / 大胡率`。
- 不出现“胜率”“头名率”。
- 只保留一张图：`净分走势`。
- 大胡统计零值在概览隐藏。
- 展示近期大胡牌谱。

## 11. 设置

只展示真实已实现功能：账号资料、记分偏好、常用分值、局内事件默认值、组局偏好、隐私/协议与退出登录。

不增加没有后端能力的假开关或占位项。

## 12. 实施约束

- 业务页面不得再次复用已经废弃的 legacy 页面 DOM 去“套皮”。
- 新页面使用独立命名空间样式，避免 `index.scss` 历史规则反向覆盖。
- 改动后必须检查最终编译 WXSS 的规则顺序，而不仅检查源 SCSS。
- 在 2C2G 服务器上禁止 `npm ci / npm install` 和并行构建。
- 微信构建、上传必须走现有 cgroup 受限流程。
